# API создания заказов

`POST /api/orders` создаёт заказ вместе с постаматом, товарами и ячейками. Поле `courier_login` необязательно: если оно передано, заказ сразу назначается существующему курьеру, иначе создаётся без курьера. Дата назначения заказа проставляется сервером автоматически при назначении.

Передайте токен из `COURIER_ORDERS_API_TOKEN` в заголовке `X-API-Token` и JSON-тело запроса:

```json
{
  "number": 1842,
  "courier_login": "aleks",
  "parcel_locker": {
    "number": "ПВЗ-07",
    "address": "ул. Ленина, 12"
  },
  "items": [
    {"name": "Вода 5 л", "quantity": 2},
    {"name": "Хлеб", "quantity": 1}
  ],
  "cells": ["A-12", "A-13"]
}
```

Номер заказа должен быть уникальным, а `courier_login` должен уже существовать в таблице `users`. Успешный ответ: `201 Created`; неверный токен: `401`; ошибка данных или повторный номер заказа: `422`.

## Список всех посылок

`GET /api/orders` возвращает все посылки, включая неназначенные. У неназначенной посылки поля `courier_login` и `courier_created_at` имеют значение `null`.

## Назначение курьера

`PATCH /api/orders/{номер_заказа}/courier` назначает или переназначает курьера по логину:

```json
{
  "courier_login": "aleks"
}
```

Например: `PATCH /api/orders/1842/courier`. Логин должен существовать в таблице `users`. В ответе возвращается обновлённая посылка, а дата назначения устанавливается сервером автоматически. Несуществующий заказ возвращает `404`.
